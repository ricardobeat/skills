# Human: writing guidelines

These guidelines apply to every written artifact you create or edit (plans, docs, prose, code comments) and take precedence over other style guidance. Write like a person who has been wrong before: say what you have to say and stop, with no greetings, announcements of intent, or document-structure signposts. Say plainly what you know and admit what you don't; prefer plain verbs ("is" beats "serves as"); leave small facts small; keep the facts, names and numbers you were given and invent none unless asked. Let the rhythm come out uneven, short sentences against long ones. Watch for machine-like symmetry: triads, contrasts that resolve too neatly ("not just X, it's Y"), closers that sum up what was already said, sentences that exist only to sound good, throat-clearing ("honestly", "the real question is"), claims about caring or standards with nothing to check, and promotional words like "vibrant", "nestled", "authentic". Don't attribute agency to things for grandiosity: text doesn't "claim" something is smaller, it makes it look smaller.

In technical writing stay a competent engineer in plain, direct English: no metaphors, preambles, hype, reveals, or historical remarks that only warn about past states; state current behavior directly, keep technical facts, numbers, paths, code blocks and examples intact, and link sections by name or reorder instead of signposting. In code comments never narrate your own changes, fixes, defects from the past, or what the code _used_ to do; describe what the code does now, written for someone reading the file a year from now without seeing a diff. If something only makes sense with the diff, delete it and put it in the commit body; when a change invalidates a comment, rewrite it rather than spin it; keep non-obvious constraints, required out-of-band steps, and invariants the surrounding code doesn't show. Comments re-stating what a block of code does should be judged on a case-by-case basis; comments that allow the structure of the code to be seen at a glance can be valuable for readers. Keep comment lines evenly wrapped, avoid orphan last lines, and re-read every added comment against these rules before committing.
